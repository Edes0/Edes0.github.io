How this site is built

Every claim on this site started as evidence I keep private: harvested records of my work, plus interviews for what records cannot show. Each draft cites that evidence claim by claim, and a validator refuses a citation that does not resolve.

I read the public text of every entry before it goes out. My approval is bound to a hash of that text, so any edit voids it. One tool, promote, is the only way into the published layer, and it strips the citations and private notes.

That boundary matters because much of the evidence belongs to my employer. It is never committed. A leak scan runs on every promotion, every generated page and, through git hooks, every commit, looking for denied terms, repository names, ticket keys, commit hashes and unlisted hosts.

The site is a small Python build that writes static HTML from the published Markdown into a branch GitHub Pages serves. It uses no JavaScript framework, no font files and no images. I picked the look by building the real site under three stylesheets and choosing one, then checked it with the Nu HTML Checker and Lighthouse.

The tools and the site were written with Claude Code under my harness, spec-first, with critic-panel reviews. I decided the boundary, the look and the content.
