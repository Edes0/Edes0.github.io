From hand-written code to agentic harness work

For my first two years at SparkVision I wrote the code by hand: features in the configurator backend landed as runs of small commits and work-in-progress snapshots, merged through pull requests.

My first attempt to give coding agents context, a set of markdown files for the backend in October 2025, was declined.

In April 2026 an agent guide landed in the backend repository, and in May I ran a workshop for the team on Claude Code skills, slash commands, hooks and specs.

This time it stuck, because we introduced it as a company alignment with AI.

At the end of May I started a versioned harness of my own, and in June I wired the company's repositories into it.

Over the summer the work changed shape. The Bring Your Own Room epic was planned as spikes and slices before any code, and its commits carried specs, glossary entries and recorded gotchas next to the code.

In September I built a shared team workspace so colleagues without my harness could use the same skills, guardrails and deploy flow.

By October a feature arrived as an epic cut into tickets, each driven to a pull request by the harness and reviewed before merge; the tile-rotation and grout-thickness epics went that way.

The harness became a project in its own right, with a guard hook, a permission charter and an evaluation suite that checks it still works after a change.

Some of its rules came from things that went wrong. A loop with no cap ran 12 rounds of finding "new" improvements until the session ran out of tokens, so every agent loop now has a hard round cap and stops when nothing serious is left or a round makes no progress. A debugging session proposed eight causes for a blank page by reading code, all wrong, until a twenty-line error boundary found the real one, so a visible symptom now gets measured, not reasoned about.
