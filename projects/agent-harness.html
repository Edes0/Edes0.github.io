Summary

A versioned Claude Code configuration: skills, hooks, rules, specs and workflow engines that take a feature from an idea to a reviewed, merged pull request, with guards that keep autonomous agents inside agreed limits. I built it and use it daily at work, and for my own projects.

What I did

  • Started the harness as a versioned set of skills, settings and a statusline, with a morning automation that scouts for upgrades, so the setup is reproducible across machines and keeps up with Claude Code's changes.
  • Built a spec-driven feature sequence — idea, spec, grilling, plan, test-first implementation, landing — with one git worktree per feature and a hand-off to the primary checkout for manual testing.
  • Built autonomous release engines that drive a queue of specs or tracker slices to open pull requests, with an independent looping review, a budget check before each item and a recorded review.
  • Built a severity-aware critic panel for plans, specs and diffs, and a test gym that measures whether it finds seeded defects.
  • Wrote a guard hook and a permission charter that decide, row by row, which agent actions run, ask or are denied.
  • Ported the harness scripts from PowerShell to Python.
  • Built evaluation tooling: a regression suite for skills, harness and model comparisons, and blind judge verdicts.
  • Added work-environment skills: cutting a product release, reading production logs from Grafana, and fetching Jenkins build output.

Outcomes

  • The team workspace is built on it and is used by six people in three departments.
